How agents remember

A course on memory in AI agents, from why a language model forgets everything between calls to how ChatGPT, Claude, Gemini, Codex, Muse, dots and Grok Bot remember across months, and how to build memory that is useful, correct and safe.

Research current to 25 November 2026 75 sources, primary documentation first 23 chapters; read in order, or jump in anywhere

What you will learn

A language model has no memory of its own between calls. Everything an agent "remembers" is text that some piece of software decided to put back in front of the model. That one fact explains the whole field, and this course builds on it, one layer at a time.

  1. Memory is a context-selection problem. A model only knows its weights and what is in its context window. Memory systems decide what goes back into that window, and context is a finite resource that degrades as it grows.23 (Chapters 1 to 3.)
  2. Four kinds of memory, borrowed from psychology, organize the design space. Working memory is the context. Episodic memory is what happened. Semantic memory is what is true. Procedural memory is how to do things.467 (Chapter 4.)
  3. Writing is the hard part, because every note is a bet on the future. Anthropic found that strong models judge what is worth saving better than fixed rules do. Telling Opus 5 to "record only failures" erased much of what memory gained it.12 (Chapter 6.)
  4. When a fact changes, there are three designs: rewrite memory (Google Memory Bank, ChatGPT), keep every version and resolve time when reading (Mem0), or stamp facts with validity intervals (Zep's Graphiti).52406164 (Chapter 9.)
  5. "Dreaming" became an industry term in 2026. OpenAI, Anthropic and Letta all run offline passes that consolidate memory from transcripts without touching model weights. Google Research uses "sleep" for something different: updating the weights themselves.40366930 (Chapters 9 and 21.)
  6. Long-running agents need memory inside a task, not just across tasks. Compaction, clearing old tool results, progress files and git let one job span many context windows.333413 (Chapters 11 and 12.)
  7. Memory is a new attack surface. A single poisoned write can steer every later session. One 2026 study injected persistent instructions into Claude Code's memory in 66.9 percent of attempts, and those instructions took effect across sessions in 81.7 percent of cases.25 (Chapter 19.)
  8. The research is lopsided. A survey of 435 works found most of the literature is about accumulating and retrieving state, not governing, recovering or relinquishing it.14 (Chapters 20 and 23.)

Part I

Foundations

Before any product or framework makes sense, four ideas have to be in place: why a model starts every call from nothing, why simply giving it more text doesn't fix that, where knowledge can live instead, and the vocabulary everyone uses for different kinds of memory.

1Why a language model forgets

A large language model is, at its core, a very large function. Text goes in. The model predicts the next small piece of text, called a token (roughly three-quarters of a word in English), appends it, and repeats. Everything the model "knows" in general is stored in billions of numbers, its weights, which were set during training and are fixed afterwards. Using the model is called inference, and nothing that happens during inference is written back into the weights. Tell a model your name, and the weights are exactly the same afterwards.

So where does a chatbot's apparent continuity come from? From the software around the model. On every turn, the application sends the model the whole conversation so far: the system instructions, every earlier message, and the new one. OpenAI's API documentation shows this directly: to keep a conversation going, you "manually manage conversation state" by passing earlier messages back in, or let the API do the bookkeeping for you with a pointer to the previous response.45 The model never remembers the conversation. It is reread, in full, every time.

That gives a precise definition of the subject. Anthropic defines agent memory as "knowledge that Claude gains from experience … and that it retains between sessions, saved as context it can read later." It explicitly excludes three neighbors: changes to the weights, in-context learning within one conversation, and compaction, the summaries that let one long task continue in a fresh context window.12 This course uses the same boundaries, then covers each neighbor in its own place: compaction in Chapter 11, weights in Chapter 21.

In short

  • A model's weights don't change when you use it, so nothing persists by itself.
  • Chat continuity comes from resending the conversation on every call.
  • "Memory" means choosing what text to put back in front of the model, and when.

2The context window is working memory, and it decays

The context window is the maximum amount of text a model can take in on one call. Everything an agent works with competes for that space: system instructions, tool definitions, the conversation, results from tools it called, documents it retrieved. By 2026 frontier windows reach a million tokens or more, which raises an obvious question: why not keep everything in context and skip memory engineering?

Because models don't use long contexts evenly. In 2023, researchers at Stanford and elsewhere showed that models answer much better when the relevant information sits at the start or end of the input than when it is buried in the middle, a pattern they called "lost in the middle."1 In July 2025, Chroma tested 18 models, including GPT-4.1, Claude 4 and Gemini 2.5, and found that "performance grows increasingly unreliable as input length grows," even on simple tasks that standard needle-in-a-haystack tests make look solved. They named the effect context rot.2

Anthropic turned this into an engineering principle. Context is "a finite resource with diminishing marginal returns." Models have an "attention budget," and good context engineering means "finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome."3 Cost points the same way. Mem0 reports that its memory retrieval averages under 7,000 tokens per query, while full-context approaches on the same benchmarks "routinely consume 25,000+ tokens per query."61 Vendor-reported

The core trade-off

Everything in context costs money, adds latency and dilutes attention. Everything left out is invisible to the model. A memory system is a policy for deciding which is which, call after call.

In short

  • Bigger context windows don't remove the need for memory, because relevance decays with length.
  • Aim for the smallest set of high-signal tokens, not the largest set that fits.

3Four places knowledge can live

When an agent "knows" something, that knowledge sits in one of four places. Each has a different capacity, speed, cost and editability, and most memory designs are about moving information between them.

Two older ideas still shape everything built since. Retrieval-augmented generation (RAG, 2020) paired a model's built-in "parametric" knowledge with a "non-parametric" index it searches at answer time, which also gives answers a source you can check.5 MemGPT (2023) went further for agents. Borrowing from "hierarchical memory systems in traditional operating systems," it let the model itself move information between a small fast tier (the context) and a large slow tier (external storage), much as an operating system pages data between memory and disk.6 MemGPT later became the company Letta, which still builds on that idea (Chapter 16).

The fourth place is easy to overlook, and it may be the most important. A lot of what an agent needs is already in the world, readable when needed: the code in the repository, the git history, what is on the screen. Anthropic's study of Claude playing Pokémon makes the point vividly. An older model stored facts like the player's money and location, which "can be read off the screen every turn, so storing it is redundant," and its records kept going out of date. A newer model saved only what the game didn't show: strategy, plans and rules it had tested.12 Claude Code applies the same discipline to code, skipping "anything it can derive from the codebase, such as architecture, file paths, or debugging fixes."31

Principle.Don't memorize what you can look up. Store what exists only because the agent worked it out: decisions, preferences, tested rules, plans.

4Four kinds of memory

The field borrowed its vocabulary from cognitive psychology, by way of a 2023 paper called CoALA (Cognitive Architectures for Language Agents). It separates a short-term working memory from three long-term kinds: episodic, semantic and procedural.4 LangChain's documentation puts the three long-term kinds in one line each: semantic memory holds "facts," episodic memory holds "experiences," procedural memory holds "instructions."67 The colors below mark the four kinds throughout the course.

Working memory

What the agent holds right now: the context window, its current plan, a scratchpad. It is fast and exact, and it is gone when the call ends.

In products: the conversation, tool results, a file just read.

Episodic memory

What happened: specific past events and actions, with their time and context. Raw transcripts and logs are episodic. So are reflections written about past attempts.

In products: session transcripts, work logs, Gemini's "episodic memory of everything it has done before."48

Semantic memory

What is true: facts and concepts, freed from the episode where they were learned. "The user is vegetarian." "Staging is at stage.example.com."

In products: ChatGPT and Claude memories, Memory Bank facts, Mem0, Zep graphs.

Procedural memory

How to do things: instructions, rules, routines and skills. It turns experience into behavior, not just knowledge.

In products: CLAUDE.md, AGENTS.md, Cursor Rules, Agent Skills, Foundry's procedural memory.

One terminology trap: LangChain notes that semantic memory "is different from 'semantic search'." Semantic memory is a psychology term for stored facts; semantic search is a retrieval technique based on embeddings.67 A semantic memory can be found by keyword search, and episodic memory can be searched semantically.

The kinds also have a history in the research that this course will keep returning to. Generative Agents (2023) gave simulated characters a "memory stream" of observations they retrieved by recency, importance and relevance, which is episodic memory with a scoring function.7 Reflexion (2023) had agents write short verbal reflections on their failures and keep them for the next attempt, which turns episodes into lessons.8 Voyager (2023) let a Minecraft agent build an "ever-growing skill library" of working code, the first convincing procedural memory for an LLM agent.9

Other axes that matter in practice

The four kinds tell you what is remembered. Real systems also differ along several other axes, and 2026 surveys add more:1514

Who writes it
A person (instruction files such as CLAUDE.md) or the agent (Claude Code's auto memory). Claude Code's docs draw the line exactly this way.31
When it is written
"In the hot path," during the reply, or "in the background" afterwards. LangChain treats this as a core design choice.67
Scope
One user, one agent, a team, an organization, or a thread. Google's Memory Bank keeps "an isolated collection of memories" for each scope.50
Substrate
Internal parametric state (weights) or external stores. This is one of the three dimensions in the 60-author 2026 survey.15
Subject
Memory about the user (personalization) or about the agent's own experience (self-improvement).15
Governance
Authority, scope, mutability, provenance, recoverability and actionability: the six axes of the Always-On Agents survey, which warns that organizing by memory type alone "strands governance, serving substrates, deletion propagation, and rollback as footnotes."14

In short

  • Working memory is the context. Episodic memory records events, semantic memory holds facts, procedural memory holds instructions and skills.
  • Who writes memory, when, for which scope, and under what governance matter as much as its type.

Part II

Mechanics

Every memory system, from a single Markdown file to a managed knowledge graph, makes the same handful of decisions. This part takes them one at a time, in the order a piece of information meets them.

5The memory lifecycle

The clearest map of the territory comes from the 2026 Always-On Agents survey. It follows each piece of state through a lifecycle in which it is "written, validated, organized, retrieved, acted upon, updated, forgotten, audited, and sometimes rolled back."14 Its authors coded 435 works and found that the literature "concentrates more heavily on accumulating and retrieving state than on governing, recovering, or relinquishing it."14 Production systems show the same imbalance. The early stages get elaborate machinery; the late ones are often an afterthought.

A simpler framing from a March 2026 survey is a "write–manage–read" loop, with systems classified by temporal scope, representational substrate and control policy.17 The two framings agree. The nine-stage lifecycle simply spells out what "manage" contains.

The survey also names five invariants a persistent agent should preserve, which an agent that resets after every session satisfies trivially: authority monotonicity, scope non-expansion, deletion propagation, provenance preservation and rollback traceability.14 In plainer terms, a remembered item should never quietly gain power, reach a wider audience than it was written for, survive a deletion, lose track of where it came from, or become impossible to undo. Each one turns up again in Part V.

6Writing: every note is a bet on the future

Writing is the hardest stage, because the agent has to decide what will matter before it knows what comes next. Anthropic puts it this way: "Memory is, occasionally, a prediction." Writing down a rule predicts the pattern will recur; writing down a verified fact predicts a future session will want to rely on it "without double-checking it."12

Who decides to write

The first ChatGPT memory, launched in April 2024, wrote only on explicit cues such as "remember I'm traveling to Singapore in July." OpenAI's own verdict is that this felt "like talking to someone who took a few notes, but still forgot everything that wasn't written down."40 Systems now combine three writers:

  • The person, through instruction files such as CLAUDE.md and AGENTS.md, or settings like Claude's memory Topics and ChatGPT's memory summary page.313840
  • The agent, during work: Claude Code's auto memory saves notes "based on your corrections and preferences," and a Grok Bot "decides on its own when something is worth keeping. It doesn't ask first."3159
  • A background process that mines past sessions, such as ChatGPT's dreaming, Codex memories and Google's Memory Bank (Chapter 9).404152

When to write: the hot path or the background

Writing during the reply ("in the hot path") makes a memory available immediately, but costs latency and pulls the agent's attention off the task. Writing afterwards ("in the background") is cheaper and better informed, but arrives late.6712 Production systems lean toward the background and add guards. Mem0 processes conversations "asynchronously (after the agent responds)."61 Codex goes further:41

  • it skips "active or short-lived sessions";
  • it waits until a chat has been idle "to avoid summarizing work that's still in progress";
  • it skips a pass when your rate limit is running low;
  • it redacts secrets from what it writes.

What to write: judgment beats rules, for strong models

Anthropic's 2026 study is the best evidence available on salience, the judgment about what is worth keeping.12

  • On a Pokémon run, Claude Sonnet 3.7 "wrote to memory indiscriminately": 413 files across 225 folders, and one badge earned. Claude Fable 5 kept nine files in two folders plus a single global.md dashboard, and earned four badges.
  • On a continual-learning task (CL-Bench 1.0), Sonnet 4.6 only produced untested theories. Opus 5 was the first to "close the loop," writing rules together with how it knew each rule was true.21
  • Adding a fixed rule, "record only failures," cost Opus 5 and Opus 4.7 "much of the performance boost that memory gave them." Anthropic's conclusion: "it helps to tell Claude what memory is for, but not how to use it."
  • Steering still helps weaker models. Prompting Sonnet 4.6 to read its memory first and to test its theories "nearly doubled its benchmark score."

Typed notes and what never to write

Giving each note a type helps both writing and retrieval. Claude Code's auto memory uses four types, recorded in YAML frontmatter, and stamps each write with a modified timestamp so later readers can see "how current the fact is":31

  • user: your role, expertise and working preferences;
  • feedback: corrections you give and approaches you confirm;
  • project: ongoing work, deadlines and decisions;
  • reference: where to find information outside the project.

Grok Bot keeps separate memories for "people and organizations, your profile, your standing instructions, and your projects."60 Mem0 classifies each memory as an event, state, plan, preference, relationship or absence.61

Equally important is what stays out:

  • Secrets. Anthropic says Claude "usually refuses" to write sensitive information to memory, and advises stripping it in code for stronger guarantees. Grok Bot removes card numbers even when hidden characters split them.3260
  • Sensitive topics such as health or beliefs, which stay out of Claude's memory unless you turn them on.38
  • Anything derivable from the codebase or the screen (Chapter 3).31

Google is candid that filters fail: Memory Bank "has been instructed to exclude sensitive or personal data," but "the system is not infallible."52

In short

  • Strong models should judge salience themselves; tell them what memory is for, not how to use it.
  • Write in the background where you can, with guards against half-finished work and secrets.
  • Type and timestamp notes, and never store anything derivable or secret.

Files won

The striking 2026 trend is how many teams converged on plain files with an index. Claude Code keeps "a MEMORY.md index and one topic file per memory."31 Letta's MemFS keeps the agent's memory in a git repository, loads root files "into the agent's system prompt on every turn," and keeps subdirectories with their own MEMORY.md "out of context until they are needed."68 Anthropic's Managed Agents mount memory stores as directories under /mnt/memory/, which the agent reads "with the same file tools it uses for the rest of the filesystem."35 Microsoft added file-based memory to Agent Framework so developers can "begin locally with an experience that is easy to inspect, version, and understand with markdown (.MD) files."56 Meta Muse exposes its memory as files such as MEMORY.md that you can read and edit.57 The reasons are practical: models are very good with files, people can read and fix them, and version control comes for free. Wikis: when structure pays and when it doesn't

Anthropic tested wikis on about 350,000 internal documents (roughly 420 million tokens) from Stainless, a company it acquired in May. As dreaming sessions scaled from 2 to 128, a wiki alone went from 13 to 48 percent of graded criteria. Wiki plus search reached 61 percent, against 53 percent for search alone. On merger questions that needed several documents, the wiki scored 87 percent against 73 percent for search. On a legal task answerable from single documents, it showed "no clear gain." In one case the wiki "grew to be larger than the raw files," which Anthropic compared to Borges's map as large as its empire.12 The lesson generalizes: structure pays when answers are scattered, and costs when they aren't.

8Retrieving: what to load up front and what to look up

Retrieval has two paths. Some memory is injected: loaded into context at the start of every session whether it is needed or not. The rest is looked up on demand, with tools or search. Getting the split right is most of the craft.

The injected layer must stay small

Anthropic is explicit about what injection costs: "Injected memories use up valuable tokens, and an incorrect note can be carried into every session," and loading a note "doesn't guarantee that Claude acts on it," because "longer instruction files reduce adherence."12 So every system caps the always-loaded layer:

  • Claude Code loads only "the first 200 lines or 25KB of MEMORY.md," warns Claude as the file nears the limit, and returns an error telling it to rewrite the index if the file goes over.31
  • Codex concatenates AGENTS.md files from the root down, and stops at 32 KiB by default.42
  • Cursor recommends keeping each rule under 500 lines.70

Look up the rest, progressively

Anthropic calls the alternative "just in time" context. Agents "maintain lightweight identifiers (file paths, stored queries, web links, etc.) and use these references to dynamically load data into context at runtime," which also allows "progressive disclosure."3 The Agent Skills standard formalizes progressive disclosure in three stages:73

  1. Discovery: at startup, load only each skill's name and description.
  2. Activation: when a task matches, read the full SKILL.md.
  3. Execution: follow the instructions, loading bundled files only if needed.

An index such as MEMORY.md plays the same role for memory. It shows the agent what it knows and where to find it.1231

Search that fuses several signals

When memory is a large collection, a single similarity score isn't enough. Mem0's 2026 retrieval scores every candidate on four signals in parallel, then fuses the rankings:61

  • semantic similarity, which suits conceptual questions;
  • BM25 keyword matching, which suits exact facts;
  • entity matching, for questions about a person or thing;
  • temporal fit, for questions about when.

LongMemEval's authors reached similar conclusions from the benchmark side. They recommend splitting sessions into smaller units, expanding index keys with extracted facts, and expanding queries with time.19 Retrieval is also partly a model behavior. In Anthropic's tests, Sonnet 5 read its memory before answering 9 times out of 10 without being told to; Sonnet 4.6 did so less than half the time.12 That is why the memory tool's built-in instruction opens: "ALWAYS VIEW YOUR MEMORY DIRECTORY BEFORE DOING ANYTHING ELSE."32

In short

  • Keep the injected layer small and curated; it is paid for, and trusted, on every turn.
  • Everything else should be found just in time, through an index or through search over several signals.

9Updating, consolidation and dreaming

Facts change. OpenAI's example is simple: memory should revise "You're going to Singapore in July" to "You went to Singapore in July 2026" once the trip ends.40 In 2026, systems handle a changed fact in one of three fundamentally different ways.

Consolidate at write. Google's Memory Bank runs extraction, then consolidation, and "checks that new memories are not duplicative or contradictory before merging them with existing memories." Its structured profiles keep "a single profile as the source-of-truth" for each schema and scope.5251

Append only. Mem0 reversed its own 2025 design. The 2025 paper described "dynamically extracting, consolidating, and retrieving" memories.63 The 2026 system makes "ADD-only extraction" its "key architectural decision": "Nothing is overwritten or deleted. When information changes, both the old and new facts survive." Time is handled by a separate pass that tags each memory with when it happened, then scored against "the query's temporal intent" at search time.61

Invalidate with time. Graphiti stores facts as entity-relationship triplets in a "bi-temporal model": "When new data invalidates a prior fact, the time the fact became invalid is stored on that fact's edge," and source episodes preserve provenance.6465 On Zep's own LongMemEval tests, this approach improved accuracy by up to 18.5 percent while cutting latency by 90 percent against baselines.66 Vendor-reported

Dreaming: consolidation as an offline job

The second big idea of 2026 is to move consolidation out of the conversation entirely, into a scheduled job that rereads history and rewrites memory. It has a research ancestor: sleep-time compute, from Letta and UC Berkeley, which lets models "think" offline about context before queries arrive. On the paper's stateful math tasks, this cut the test-time compute needed for the same accuracy by about 5 times.11 Four production versions now exist:

OpenAI (ChatGPT)
The first version of dreaming, in April 2025, was "a method for ChatGPT to automatically curate memories in the background by referencing chat history." On June 4, 2026, OpenAI launched "a significantly more capable and compute-efficient memory architecture built on top of dreaming," which its evaluations call Dreaming V3. OpenAI also cut the compute needed to serve it "by approximately 5x" so free users could get it. Its own evaluations, from 2024 to 2026, show factual recall rising from 41.5 to 67.9 to 82.8 percent, preference adherence from 31.4 to 55.3 to 71.3 percent, and staying correct over time from 9.4 to 52.2 to 75.1 percent.40
Anthropic (Managed Agents)
Launched as a research preview on May 19, 2026.37 A dream is an asynchronous job that takes a memory store plus 1 to 100 past sessions and "produces a new, reorganized memory store: duplicates merged, stale or contradicted entries replaced with the latest value, and new insights surfaced." The input store "is never modified," so you can review the output and discard it. Optional instructions steer it, and it is billed at standard token rates.36 Harvey reported completion rates up about 6 times in its tests.37
Letta
Dreaming runs as background subagents. It can be triggered every N steps or on each compaction, and either reminds the agent to update memory or launches a dreaming subagent on its own. It edits memory in separate git worktrees so it never blocks the main agent.6968
Codex
A two-phase pipeline. One model extracts memories from each chat, and a separate consolidation model merges them across chats. Each model can be configured.41

Anthropic's research shows what dreaming can do beyond deduplication. In the Pokémon example, Claude had written down the wrong side of the map for a landmark. A dream checked the note against the transcript and corrected it, and the corrected run went straight back into the cave while the uncorrected run never got past the mountain. Dreaming also built wikis, "promote[d] notes up the memory hierarchy," and filled gaps: a second pass found nine links to a missing page and repointed them.12 Its instructions matter as much as the mechanism. A wiki built with generic instructions kept only 41 of 57 contract facts, because parallel agents overwrote one another. After Claude rewrote its own instructions to give each contract its own page, quoting terms word for word, all 57 survived.12

Two different things called "dreaming"

In OpenAI, Anthropic and Letta products, dreaming rewrites external memory: an Anthropic dream outputs a new memory store, and Anthropic's definition of agent memory explicitly excludes "changes to their weights."3612 Google Research's 2026 "sleep framework" does the opposite: during a sleep phase it "updates its numerical weights using self-generated practice examples."30 The same metaphor names two different mechanisms. Chapter 21 covers the second one.

In short

  • Pick a policy for changed facts: rewrite, append and resolve at read time, or keep validity intervals.
  • Background consolidation ("dreaming") is the 2026 default for keeping memory clean, correct and small.
  • Never overwrite the input to a consolidation pass. Keep it so a bad pass can be reviewed and undone.

10Forgetting

A memory that only grows eventually fails. Older notes go stale, as the Pokémon example showed. Stores fill up: Anthropic's memory stores cap at 10,000 memories, and writes past that "fail."35 Retrieval gets noisier. And people have a right to make an agent forget. Forgetting comes in five forms:

Expiry
Microsoft Foundry sets a time-to-live when a memory store is created, "automatically retiring older, lower-value memories."56 Mem0 memories can carry an expiration_date, after which they are hidden from search but still fetchable by ID.62
Decay
MemoryBank (2023) borrowed the Ebbinghaus forgetting curve, so memories weaken over time unless reinforced by recall.10
Consolidation
Dreams merge duplicates and replace contradicted entries, which is forgetting by rewriting.36
User deletion
Claude lists everything it remembers under Topics, where you can edit or delete any item.38 Muse's "forget skill" removes a topic from memory "to the best of its ability."57 Grok Bot forgets when you ask in chat.59 OpenAI's enterprise documentation says "individual dot memories cannot be deleted": you delete the whole dot.47
Redaction
Anthropic's memory stores keep an immutable version for every change. "Redact" scrubs content from a past version "while preserving the audit trail," for example to remove a leaked secret or fulfil a deletion request.35

Deletion is harder than it looks, because copies multiply. A fact can live in the memory store, in a derived note, in a wiki page, in a summary, in an old version and in a backup. The Always-On Agents survey titles one section "Forget: deletion as a retrieval edit, not an erasure," and lists deletion propagation among the invariants that persistent agents must preserve.14 OpenAI's guidance for dots admins illustrates the point: removing access to a source "stops future access but can leave a derived note intact."47

Principle.Design forgetting as a propagation problem. Every derived artifact should point back to its source, so that one deletion request can find and remove every copy.

Part III

Long-running agents

Part II covered memory across sessions. An agent that works for hours or days also needs memory within one task: its own transcript overflows the context window long before the job is done.

11Compaction and context editing

Compaction "replaces the older turns of a conversation with a summary," keeping "a long conversation or agent task inside the context window" and keeping "the active context small, because response quality degrades as a conversation grows."33 Context editing is the finer tool: it removes specific items, such as old tool results, rather than summarizing everything.34

Two providers, two philosophies

Anthropic's compaction produces a summary that Claude writes. You can trigger it yourself (on demand) or have the API trigger it at a token threshold. On-demand compaction can keep recent turns verbatim and can run in the background while work continues.33 OpenAI's server-side compaction instead returns an encrypted item that "carries forward key prior state and reasoning into the next run using fewer tokens." OpenAI says it "is opaque and not intended to be human-interpretable." It is compatible with zero data retention when requests aren't stored, and clients can drop everything before the latest compaction item.44

The difference matters for anyone building on top. A readable summary can be inspected, audited and corrected when it drops something important. An opaque item can carry hidden reasoning state compactly, but you cannot check what it kept. Inferred

Clearing before summarizing

Anthropic calls clearing old tool results "one of the safest lightest touch forms of compaction": once a tool result has been used deep in the history, the agent rarely needs the raw output again.3 Its API clears the oldest tool results first. It can also clear old thinking blocks, with separate settings for how much recent reasoning to keep.34 Combined with the memory tool, clearing becomes a memory mechanism. As the context nears the clearing threshold, "Claude receives an automatic warning to preserve important information," so it can write what matters to memory files before the raw material disappears.34

Principle.Compaction prompts fail by losing details whose importance only shows up later. Anthropic advises tuning them on real agent traces, starting by maximizing recall, so the prompt "captures every relevant piece," and only then cutting for precision.3

12Harnesses for work that spans many context windows

Compaction keeps one session going. Work that spans days needs more: a way for each fresh session to pick up exactly where the last one stopped. Anthropic's November 2025 study of long-running coding agents names two failure modes. Agents try to "one-shot" the whole job. Or, later on, a new instance "would look around, see that progress had been made, and declare the job done."13 Their fix is a harness: the code around the model that sets up its environment, files and instructions.

Several details from that study are worth copying exactly:13

  • A feature list as a contract. The initializer expanded the user's prompt into more than 200 testable features. Later agents could only change each feature's passes field, under instructions like "It is unacceptable to remove or edit tests."
  • JSON over Markdown for that list, because "the model is less likely to inappropriately change or overwrite JSON files compared to Markdown files."
  • One feature at a time, which turned out to be "critical to addressing the agent's tendency to do too much at once."
  • Git as memory and undo. Each session commits with descriptive messages and writes a progress summary, so the next one can understand the state, "use git to revert bad code changes and recover."

The same idea is built into Anthropic's memory tool, which adds a protocol to the system prompt that includes: "ASSUME INTERRUPTION: Your context window might be reset at any moment, so you risk losing any progress that is not recorded in your memory directory."32

Many agents, shared memory

When several agents work at once, memory becomes shared state, with all the classic concurrency problems. Anthropic's managed memory stores offer:35

  • optimistic concurrency: pass a content_sha256 precondition, and an update "only applies if the stored content hash still matches";
  • read-only mounts for agents that only consume shared reference material;
  • up to 8 stores per session, so different parts of memory can have different owners or access rules.

The risk is real. In Anthropic's wiki experiment, several agents wrote to one shared table, and the wiki lost 16 of 57 contract facts, partly because agents "had overwritten one another's work."12 Subagents usually get isolated context on purpose. In Claude Code, the main conversation's auto memory "isn't loaded into subagents," which keep their own memory directories if you enable them.31

In short

  • For multi-day work, treat the filesystem and git as the agent's memory: a progress log, a feature contract and frequent commits.
  • Make the work incremental, and make every session leave the environment clean.
  • Shared memory needs concurrency control; isolated subagents avoid the problem.

13Procedural memory: instructions, skills and learned procedures

Microsoft's Foundry team describes the gap procedural memory fills: "agents often know the right facts and still fail the task because they do not execute the right procedure."56 Procedural memory in 2026 comes in three forms, from most to least human-authored.

Instruction files

The oldest form is a file of standing instructions that loads into every session. AGENTS.md is "a simple, open format for guiding coding agents," used by more than 60,000 open-source projects.72 Codex builds an instruction chain from ~/.codex/AGENTS.md down through each directory to the one you are working in, and later files override earlier ones.42 Claude Code reads CLAUDE.md at four scopes: managed policy for an organization, user, project and local. It reads AGENTS.md when a repository has no CLAUDE.md, and supports path-scoped rules in .claude/rules/.31 Cursor offers project, user and team rules, with team rules taking precedence.70

Two warnings apply to every instruction file. They are advisory: Claude Code's docs state that CLAUDE.md and auto memory "aren't enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead."31 And OpenAI tells Codex users to "Keep required team guidance in AGENTS.md or checked-in documentation. Treat memories as a helpful recall layer, not as the only source for rules that must always apply."41

Skills

A skill packages a procedure: "a folder containing a SKILL.md file" with metadata and instructions, plus optional scripts and references. The format "was originally developed by Anthropic" and released as an open standard. Agents load skills by progressive disclosure, keeping "many skills on hand with only a small context footprint."73 Letta versions agent-owned skills inside the agent's memory repository, so skills travel with the agent.68

Procedures learned from experience

The newest form is procedural memory the system extracts by itself. Its research ancestor is Voyager's skill library.9

  • Microsoft Foundry audits agent trajectories to find "successful patterns, inefficient routes, and missing steps." It stores procedures with both "when to use" (context, preconditions, signals) and "what to do" (ordered actions, required checks, tool usage).56
  • Google's Gemini agent keeps "procedural memory for how a job gets done, including skills it writes for itself."48
  • ChatGPT's Computer History watches your activity in apps you allow, and when it "notices repeatable work," it suggests a skill or automation.43

A counter-example worth knowing

Cursor shipped automatic "Memories" in 2025 and then removed them in version 2.1.17. Its support reply told users to export memories into Rules.71 Cursor's docs now say: "Large language models don't retain memory between completions. Rules provide persistent, reusable context at the prompt level."70 For a tool built around a shared codebase, explicit, versioned, team-reviewed instructions won out over notes generated automatically. Teams building agents should weigh that choice deliberately.

In short

  • Procedural memory is behavior: instruction files, skills, and procedures learned from successful runs.
  • Instructions are advisory. Enforce hard rules with code, such as hooks and permissions.

Part V

Trust: measuring, securing and governing memory

Memory makes an agent more useful and more dangerous at the same time. This part covers how to tell whether a memory system works, how it gets attacked, and what it owes the people it remembers.

Evaluating your own system

Measure at least five things together:

  1. Accuracy on questions that need memory.
  2. Cost, as context tokens per query.
  3. Latency, including the cost of memory upkeep.
  4. Consistency over repeated runs, as in Microsoft's pass^5.
  5. Freshness as time passes, as in OpenAI's "staying correct over time."

The first three are Mem0's framing of the problem.612240 Then add adversarial tests from Chapter 19. A memory system that only gets better at recall can also get better at recalling an attacker's instructions.24

19Memory security

Prompt injection is when content an agent reads, such as a web page, an email or a file, carries instructions the agent then follows. Without memory, an injection lasts one session. With memory, "a single adversarial memory write can exert long-term influence over agent behavior."24 This is memory poisoning, and in 2026 it became a research field of its own.

What the 2026 research found

  • No direct access is needed. The eTAMP attack poisons a web agent's memory "through environmental observation alone": viewing a manipulated product page is enough, and the poison activates later "on different websites." Attack success reached 32.5 percent on GPT-5-mini and 23.4 percent on GPT-5.2. Success rose up to eightfold when agents were struggling with dropped clicks or garbled text, and "more capable models are not more secure."23
  • Harnesses are targets. PMPA embedded instructions in ordinary external sources, and got agents to write them into persistent memory. On Claude Code it achieved a 66.9 percent injection success rate and an 81.7 percent cross-session attack success rate. On OpenClaw the figures were 73.7 and 55.5 percent. A prompt-level defense "provides limited protection once the persistent memory has been poisoned."25
  • Aggressive memory is riskier. MPBench identifies four memory write channels, nine structural vulnerabilities and six classes of attack. It shows that "agents designed to write and retrieve memory more aggressively are more exploitable," and that "existing prompt injection defenses fail to cover memory poisoning attacks."24
  • Poison can sleep. Adversarial content can lie dormant in an assistant's memory and influence later interactions.26

These are research preprints with attack-specific setups. Read the rates as evidence that the risk is real, not as general base rates.

What products document as defenses

  • Scope writes. Anthropic warns that memory stores "attach with read_write access by default," so "a successful prompt injection could write malicious content into the store. Later sessions then read that content as trusted memory." It recommends read_only for anything the agent doesn't need to change.35
  • Quarantine untrusted sessions. Codex can keep chats that used MCP tools, web search or tool search out of memory generation entirely.41
  • Validate paths and content. The Anthropic memory tool docs require blocking directory traversal and recommend stripping sensitive data, capping file sizes and expiring old files.32
  • Keep history. Immutable versions with redaction, Zep's source episodes and Mem0's SQL history log all make it possible to trace a bad memory and roll it back.356561
  • Don't confuse memory with policy. Claude Code's instruction files and memory "aren't enforced configuration"; hard limits belong in hooks and permissions.31

Principle.Treat every memory write as a privileged action and every memory read as untrusted data. The most effective single control is refusing memory writes from any context that has read untrusted content.

20Privacy and governance

An agent that remembers holds a growing profile of a person. That creates obligations that a stateless chatbot never had.

What people should be able to do

  • See it. Claude lists everything under Topics. ChatGPT shows a memory summary. Microsoft's Foundry portal shows stored memories. Muse exposes the files themselves.38405657
  • Change and delete it, item by item where possible (Chapter 10), and know when they can't. Enterprise dots, for example, delete only as a whole.47
  • Keep sensitive things out. Claude excludes health and beliefs unless you opt in. Codex redacts secrets. Computer History never includes screenshots, audio or private browsing.384143
  • Talk without being remembered. Claude introduced incognito chats with memory in 2025.38
  • Leave with it, through import and export (Chapter 14).3954

What operators must track

Retention differs between memory surfaces, even within one company. Anthropic's client-side memory tool is eligible for zero data retention, because the storage is yours. Its hosted memory stores are not, and keep past versions for 30 days.3235 OpenAI's server-side compaction is compatible with zero data retention when requests aren't stored.44 The Always-On Agents survey offers the most complete governance checklist available. For each stored item, record its authority, scope, mutability, provenance, recoverability and actionability. And preserve its five invariants: authority monotonicity, scope non-expansion, deletion propagation, provenance preservation and rollback traceability. Its pilot evaluation protocol scores "state mutation and recovery obligations rather than answer quality alone."14

In short

  • Make memory visible, editable, excludable and exportable.
  • Know the retention rules of every surface where memory lives.
  • Give each item its provenance and scope, so it can be audited, deleted everywhere and rolled back.

Part VI

The frontier, and building your own

Everything so far keeps the model fixed and changes what it reads. The research frontier is starting to change the model itself. The course then closes with a design you can build from.

21Memory in the weights

External memory has two permanent costs. It has to be retrieved every time, and the model never truly absorbs it. The alternative is parametric memory: knowledge written into the model's own weights. Updating weights has always run into catastrophic forgetting, which Google Research describes as "a fundamental issue where learning new tasks severely degrades performance on previously learned ones."30 Three lines of research from one group at Google show where this is heading.

Titans (December 2024)
Adds "a new neural long-term memory module that learns to memorize historical context." Attention acts as short-term memory and the neural memory as "a long-term, more persistent, memory," scaling to context windows larger than 2 million tokens.27
Nested Learning (December 2025)
Reframes a model as "a set of nested, multi-level, and/or parallel optimization problems, each of which with its own context flow." It introduces a "Continuum Memory System" and a sequence model that "learns how to modify itself."28
Language Models Need Sleep (June 2026)
A "Sleep" paradigm with two stages. Memory consolidation distills "short-term fragile memories into stable long-term knowledge with replay." Then "Dreaming" uses reinforcement learning to "generate a curriculum of synthetic data to rehearse new knowledge."29 Google's October 2026 explainer describes the model unlocking "pre-allocated Mixture-of-Experts (MoE) memory blocks" during sleep, and updating "its numerical weights using self-generated practice examples."30

Meanwhile, model makers are training models to use external memory better. Meta's Muse Wonder introduced "Active Memory" ("carrying important context about you across conversations and actively retrieving the details relevant to the task at hand").75 Anthropic reports that newer Claude models judge salience, read their memory unprompted and close learning loops that older models couldn't.12

22Building your own: a reference memory architecture

Here is the memory subsystem I would build today for a long-running agent, assembled from the strongest documented choice at each stage. Every box exists in some 2026 product. The arrangement is my synthesis. Inferred

Build it in this order

  1. Instructions and a progress file. Start with an AGENTS.md-style instruction file and a file-based progress log, plus git. This alone carries a long-running agent a long way (Chapter 12).1372
  2. Agent-written notes. Add typed, timestamped notes behind a short index with a hard size cap. Tell the model what memory is for, not how to use it (Chapter 6).3112
  3. The write gate. Refuse writes from untrusted contexts, strip secrets, and scope every store before shipping to real users (Chapter 19).4135
  4. Versions and provenance. Every change becomes a version that points to its source, so you can audit, redact and roll back (Chapter 10).3565
  5. Consolidation. Add a background pass that writes a new version for review, never in place. Point it at information likely to change (Chapter 9).3612
  6. Search. Add multi-signal search when the store outgrows its index: semantic, keyword, entity and time (Chapter 8).61
  7. The rest. Add procedural learning, shared team memory with review queues, and portability last (Chapters 13 and 14).5660

23Open questions

  • When should memory be written? Anthropic names this the first open question: writing in the moment "draws Claude's attention away from its main task," while dreaming outputs "may not be immediately accessible."12
  • How often should memory be re-verified? Checking everything continuously is too expensive, so dreaming may need to focus "on information that's likely to change," on a schedule tuned to "how often memories are accessed."12
  • Should transcript search be the foundation? Search over raw history avoids accumulated errors, but structured representations help when answers are scattered across many sources.12
  • Can memory survive 10 million tokens? Temporal reasoning and event ordering collapse at that scale in the best-documented results.61
  • Will portability get a real format? Today, moving memory between assistants means pasting prose (Chapter 14).
  • Can governance catch up? The literature still favors accumulation over deletion, rollback and audit.14
  • Will weights become the memory? Sleep-style consolidation into parameters is promising research. Per-user deletion and isolation remain unsolved (Chapter 21).29

Glossary

Agent
A model that works in a loop: it uses tools, observes the results, and decides what to do next toward a goal.
Always-loaded layer
Memory injected into context at the start of every session, such as instruction files and a memory index.
Bi-temporal
Recording both when a fact was true in the world and when the system learned it, so history and current state can both be queried.
Compaction
Replacing older parts of a conversation with a summary, or an opaque compressed item, so a long task fits in the context window.
Consolidation
Merging, correcting and reorganizing memories, usually in the background.
Context editing
Removing specific items, such as old tool results, from the conversation sent to the model.
Context rot
The decline in a model's reliability as input length grows.
Context window
The maximum amount of text a model can read on a single call.
Dreaming
In products, an offline job that rereads past sessions and rewrites external memory. In Google's research, a phase that updates model weights.
Episodic memory
Memory of specific past events and actions.
Harness
The software around a model that runs the agent loop and manages tools, files, memory and context.
Hot path
Work done during the response, which adds latency, as opposed to background work.
Inference
Running a trained model to produce output. It doesn't change the weights.
Just-in-time context
Keeping references (paths, queries, links) and loading the actual content only when it is needed.
Memory poisoning
Getting malicious content written into an agent's memory so that it influences later sessions.
Memory store
The persistent place memories live: a folder, a database, a graph, or a managed service.
Parametric memory
Knowledge stored in a model's weights.
Procedural memory
Memory of how to do things: instructions, rules, skills, learned procedures.
Progressive disclosure
Loading only short descriptions up front, and the full content when a task calls for it.
Provenance
A record of where a memory came from, such as the episode or document it was derived from.
RAG
Retrieval-augmented generation: retrieving documents at answer time and adding them to the model's context.
Salience
How worth remembering something is, judged at the moment it happens.
Semantic memory
Memory of facts and concepts, separated from where they were learned. Not the same as semantic search.
Skill
A packaged procedure, typically a folder with a SKILL.md, that an agent loads on demand.
Token
The unit of text a model reads and writes, roughly three-quarters of an English word.
Weights
The numbers learned in training that encode a model's general knowledge and abilities.
Working memory
What the agent holds right now; for a language model, its context window.
